# API Guidelines

## Purpose
Define the standards and conventions for designing, implementing, and documenting IRIS API endpoints.

## Responsibilities
- Establish API design conventions
- Define request/response format standards
- Document error handling patterns
- Guide API versioning strategy
- Set documentation standards

## Design Goals
- **Consistent**: All endpoints follow same patterns
- **Restful**: RESTful principles wherever applicable
- **Self-documenting**: APIs are clear from their definition
- **Backward-compatible**: Versioning prevents breaking changes

## Components

### URL Conventions
- Use nouns, not verbs: `/auth/login` not `/auth/login_user`
- Plural for collections: `/users`, `/models`
- Nest for relationships: `/users/{id}/subscriptions`
- Kebab-case for multi-word: `/privacy-profiles`

### Request/Response Format
```json
// Success Response
{
  "status": "success",
  "data": {},
  "meta": {
    "page": 1,
    "total": 100
  }
}

// Error Response
{
  "status": "error",
  "error": {
    "code": "INVALID_INPUT",
    "message": "User-friendly error message",
    "details": {}
  }
}
```

### HTTP Methods
| Method | Purpose | Idempotent |
|--------|---------|------------|
| GET | Retrieve resources | Yes |
| POST | Create resources | No |
| PUT | Full update | Yes |
| PATCH | Partial update | No |
| DELETE | Remove resources | Yes |

### HTTP Status Codes
| Code | Usage |
|------|-------|
| 200 | Success |
| 201 | Created |
| 400 | Bad request |
| 401 | Unauthenticated |
| 403 | Forbidden |
| 404 | Not found |
| 429 | Rate limited |
| 500 | Internal error |

## Data Flow
Client → Request → Middleware (auth, rate-limit) → Router → Service → Response

## Public Interfaces
- All endpoints documented via OpenAPI (auto-generated by FastAPI)
- Example requests and responses in documentation
- Authentication requirements per endpoint

## Configuration
- API prefix: `/api/v1` (versioned)
- Rate limit: `rate_limit_per_minute` (default: 60)
- Max request size: `max_request_size_mb` (default: 10)

## Dependencies
- FastAPI (API framework)
- Pydantic (request/response validation)
- OpenAPI (documentation)

## Security Considerations
- All endpoints require authentication unless explicitly public
- Input validation is mandatory (Pydantic schemas)
- Rate limiting prevents abuse
- CORS is configured explicitly, not open to all origins
- Error messages do not leak internal details

## Failure Recovery
- Validation failure → 400 with specific field errors
- Resource not found → 404
- Internal error → 500 with generic message (log details internally)

## Future Improvements
- Phase 2: API versioning through URL prefix
- Phase 3: GraphQL support for complex queries

## Engineering Notes
Design APIs for the frontend developers who will use them.

## Acceptance Criteria
- All endpoints follow the URL naming convention
- All responses use the standard format
- All endpoints have OpenAPI documentation
- Input validation is enforced on all POST/PUT/PATCH endpoints
- Rate limiting is configured
